# 旅行行程规划器（Trip Planner）

## Overview

把模糊的旅行想法变成一份可直接执行的行程表：分天分时段安排景点、美食、交通，标注预算和避坑提示。核心流程：收集信息 → 查证关键事实 → 生成行程表 → 交代注意事项。

## 工作流程

### 第 1 步：收集旅行信息

从用户消息中提取以下信息，**缺失的关键项必须追问，一次问完**：

| 信息 | 必需 | 说明 |
|---|---|---|
| 目的地 | ✅ | 城市或地区 |
| 出行天数 | ✅ | 具体日期更好（可用于查天气与节假日人流） |
| 预算范围 | ✅ | 决定住宿、餐厅、交通档次 |
| 同行人 | ⬜ | 独自 / 情侣 / 带老人小孩（影响节奏与景点选择） |
| 偏好 | ⬜ | 自然风光 / 人文历史 / 美食 / 购物 / 小众打卡 |

追问示例：「为了帮你排行程，告诉我一下：去几天？大概预算多少？和谁一起去？」

### 第 2 步：查证关键事实

生成前**必须联网核实**以下信息，不得凭记忆编造：

1. 景点是否正常开放（营业时间、是否需预约、闭馆日）
2. 门票实时价格
3. 城市间的交通方式与大致耗时（高铁/航班班次可用搜索确认）
4. 目的地当前是否有大型活动、管制或天气预警

查询结果标注在行程表对应条目上；查不到的信息明确写「出行前请自行确认」，不许编造价格和时间。

### 第 3 步：生成行程表

使用 `assets/itinerary-template.md` 模板，遵守以下排程规则：

1. **节奏原则**：每天上午安排 1 个主景点 + 下午 1-2 个顺路景点，同一天的景点必须在地理上顺路，单日通勤不超过 1.5 小时
2. **留白原则**：每天至少留 2 小时自由时间；行程表的最后一晚不排满，方便用户临时加项
3. **餐饮具体化**：每餐给出 1 个具体推荐 + 1 个备选，注明人均价格
4. **交通写清楚**：景点之间的移动方式（地铁几号线/打车约几分钟/步行几分钟）
5. **预算分解**：按「住宿 / 交通 / 门票 / 餐饮 / 其他」五类给出预算表，总计不超过用户预算
6. **避坑提示**：每个城市至少 3 条真实有用的提示（如需提前预约、别在景区门口打车、某景点周一闭馆等），禁止空话（如「注意安全」「提前规划」）

### 第 4 步：输出与确认

1. 行程表以 Markdown 输出给用户
2. 明确询问：「需要调整节奏（松一点/紧一点）、更换某个景点，还是导出为文件？」
3. 用户确认后保存为 `trip-<目的地>-<天数>天.md`

## 示例

用户：「帮我做一份成都 3 天的攻略，预算 3000，两个人，爱吃辣。」

要点核对后输出（节选）：

```markdown
# 成都 3 日游行程表（2 人 · 预算 3000 元）

## D1（周五）| 市中心经典线
- 09:00 人民公园 → 鹤鸣茶社喝茶（人均 30 元），体验本地慢生活
- 11:30 午餐：小名堂担担甜水面（人均 40 元）；备选：洞子口张老二凉粉
- 14:00 武侯祠（门票 50 元/人，提前在公众号预约）→ 锦里步行街
- 18:00 晚餐：马路边边麻辣烫（人均 70 元）
- 交通提示：全天景点集中在地铁 3 号线沿线，打车单程均 <15 分钟

## 预算分解（2 人 3 天）
| 项目 | 金额 | 说明 |
|---|---|---|
| 住宿 | 1200 | 春熙路附近连锁酒店 ×3 晚 |
| 门票 | ~400 | 武侯祠、大熊猫基地等 |
| ...
```
